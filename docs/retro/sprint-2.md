## Start（下轮开始做）

1. **每天开工先在群里报"我今天改哪几个文件"**，一句话。本轮有两次两个人写同一块（#7 重写 QuestionCommandService、#2 与 #4 同时改 Discovery 三个文件），都是因为没人知道对方在动什么。
2. **PR 标题里带上改动的文件或模块名**。现在只写"实现 XX 服务"，评审的人没法预判会不会冲突。
3. **合并顺序由 SM 统一排**：先小后大、先无冲突后冲突。本轮 #4 先合，直接让 #2 变成 dirty，本来排一下就能避免。

## Stop（下轮不要做）

1. 停止在旧分支上继续堆代码。分支落后 main 三小时以上就该 rebase，不要等冲突了才处理。
2. 停止让一个人跨 Sprint 同时领 S2 和 S3 的活。① 在 Question 还没绿的时候去写 Reputation，#7 就是这么来的。
3. 停止改了分工表却不发通知。本轮 v3 → v4 改过一次，队友按 v3 开工，直接产生重复劳动。

## Continue（下轮继续保持）

1. **评审留 PR 评论**。#10 就是按 ③ ① 的意见修出来的，评论写在 PR 上比在群里说有效得多。
2. **一个 PR 一个主题**。本轮 9 个 PR 没有一个是混着两件事的，合并起来很省事。
3. **截图当场截**。CI 记录、PR 页面、看板状态都带时间，事后补不出来。
