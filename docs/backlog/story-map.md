# 用户故事地图（User Story Map）

> 骨架：用户从未注册到成为活跃贡献者的完整路径。
> 横轴 = 用户活动（backbone），纵轴 = 该活动下的具体故事，越靠下越晚做。

## 走骨架（Walking Skeleton）

```mermaid
flowchart LR
    A[注册/登录] --> B[浏览与搜索]
    B --> C[提问]
    C --> D[回答]
    D --> E[互动]
    E --> F[成长]
```

蓝 = Sprint 1 的 MVP 切片，黄 = Sprint 2，粉 = Sprint 3。

## 故事地图

| 活动 | 注册/登录 | 浏览与搜索 | 提问 | 回答 | 互动 | 成长 |
|---|---|---|---|---|---|---|
| **第一层**（必须有） | 邮箱注册<br>登录/登出 | 问题列表<br>按课程筛选 | 发布问题<br>打标签 | 提交回答 | 投票（赞/踩）<br>采纳最佳答案 | 声誉累计 |
| **第二层**（体验） | 记住登录态<br>密码强度校验 | 关键词搜索 | 悬赏提问 | 编辑自己的回答 | 评论 / 二级回复<br>@ 提醒 | 徽章<br>排行榜 |
| **第三层**（打磨） | 选课审批 | 相关问题推荐<br>热门标签 | Markdown 预览 | 教师认证 | 通知中心 | 个人主页 / 台账明细 |
| **第四层**（以后） | 第三方登录 | 个性化推荐 | 草稿箱 | 回答模板 | 举报与折叠 | 学院榜单 |

## 切片说明

| 切片 | 包含 | 点合计 | 对应 Sprint |
|---|---|---|---|
| **MVP（走骨架）** | 注册 + 列表 + 提问 + 详情 | 8 | S1 |
| **可用（能闭环）** | 回答 + 采纳 + 投票 + 认证 | 13 | S2 |
| **好用（能发现）** | 搜索 + 相关推荐 + @提醒 + 通知 | 23 | S3 |
| **完整（能激励）** | 悬赏 + 徽章 + 排行榜 | 18 | S3/S4 |
| **治理** | 封禁 + 删内容 + 课程管理 | 8 | S4 |

## 为什么这么切

1. **先做闭环再做亮点**：没有"提问→回答→采纳"这条闭环，搜索和排行榜都没有数据可展示。
2. **认证与悬赏放后面**：它们依赖身份与账本，而这两块是骨架里最复杂的部分。
3. **移动端最后**：AppShell 的结构决定了响应式改造成本，先别过早锁定布局。
