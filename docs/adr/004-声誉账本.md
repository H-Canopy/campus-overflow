# ADR-004：声誉采用只追加账本 + 定期对账

**状态**：已接受 ｜ **驱动特征**：可测试性、安全性 ｜ **相关场景**：QS-05、FF-8

## 背景
声誉是激励体系的核心，学生会强烈关注其正确性；而“直接 `UPDATE users SET reputation = reputation + 15`”
无法回答“这 15 分从哪来”，出现异常时也无法修复。

## 决策
所有声誉变动写入 `rep_ledger`（只追加，不 UPDATE / DELETE），`rep_account.reputation` 是其派生汇总；
账本唯一键 `(event_id, user_id, reason)` 保证事件重复投递时天然幂等；
每日定时任务比对“余额 = 流水之和”，不一致数量以 `co_reputation_mismatches` 指标暴露（适应度函数 FF-8）。

## 后果
- 正面：任何一次加减分都可追溯与解释；重放事件安全；作弊排查与人工更正有据可依。
- 负面：写放大（一次动作两张表）；账本会持续增长，需要按学期归档。

## 被否决的替代方案
- 只存汇总值：不可追溯、不可幂等，出错后无法自愈。
- 每次实时聚合账本求和：读放大严重，排行榜与详情页都会受影响。
