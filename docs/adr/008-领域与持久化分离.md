# ADR-008：领域对象与 JPA 实体分离

**状态**：已接受 ｜ **驱动特征**：可测试性、可演进性 ｜ **相关场景**：FF-1

## 背景
若领域聚合直接标注 `@Entity`，领域模型就被 JPA 的要求（无参构造、可变字段、延迟加载代理）绑架，
单元测试也需要启动持久化上下文；而课程的核心目标之一就是让学生体会“领域模型是纯粹的业务模型”。

## 决策
领域层是纯 Java（零框架依赖），仓储**接口**定义在领域层；基础设施层提供 `*JpaEntity` 与 `*RepositoryAdapter` 完成映射。
计数器类字段（分数、回答数、浏览数）不由聚合回写，而由原子 `UPDATE` 维护，避免“读-改-写”覆盖并发增量。

## 后果
- 正面：领域测试毫秒级、无容器；更换持久化技术只影响适配器；聚合边界与事务边界更清晰。
- 负面：存在映射样板代码（约每个聚合 40 行）；需要显式处理乐观锁版本号的搬运。

## 被否决的替代方案
- 聚合直接作为 JPA 实体：写起来快，但领域层被框架污染，FF-1 无法成立，也难以讲清六边形架构。
