# ADR-007：前后端以 OpenAPI 契约协作

**状态**：已接受 ｜ **驱动特征**：可演进性（团队并行）

## 背景
5 人小组需要前后端并行开发；若接口靠口头约定，联调阶段会集中爆发返工。

## 决策
后端用 springdoc 从注解生成 OpenAPI 3 文档（`/v3/api-docs`，UI 在 `/swagger-ui.html`）；
错误响应统一为 RFC 9457 Problem Details 并扩展业务 `code`；分页统一为 `{items,total,page,size}`；
时间统一为 UTC ISO-8601；接口变更必须先改契约、再改实现。

## 后果
- 正面：前端可据此生成类型或先行 Mock；错误处理只需写一次；Swagger UI 也是最好的验收与答辩工具。
- 负面：注解与实现可能漂移（靠集成测试兜底）；生产环境需关闭 Swagger UI。

## 被否决的替代方案
- 手写接口文档：几乎必然过期。
- GraphQL：学习成本与鉴权复杂度对本课程过高。
