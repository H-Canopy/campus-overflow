# ADR-005：搜索使用 MySQL 8 ngram 全文索引

**状态**：已接受（标记为可演进点） ｜ **驱动特征**：简单性（硬约束）、可演进性 ｜ **相关场景**：QS-02

## 背景
搜索必须支持中文。MySQL 默认全文解析器按空格分词，对中文几乎无效；而引入 Elasticsearch 会增加一个需要运维的有状态组件，
超出课程团队的能力与预算（约束 OC-2、OC-5）。

## 决策
使用 InnoDB `FULLTEXT ... WITH PARSER ngram`（`ngram_token_size=2`），检索走 `MATCH ... AGAINST (... IN BOOLEAN MODE)`，
每个词项转为必须出现的短语。搜索能力封装在 `SearchPort` 端口后面，另提供 `LikeSearchAdapter` 作为对照实现，
通过配置 `co.discovery.search.engine` 切换。**建索引前必须关闭停用词**（否则含停用词字符的 ngram 词元会被丢弃，英文检索失效）。

## 后果
- 正面：零额外组件；中英文可用；查询相关度由 MySQL 提供；替换为 Elasticsearch 只需新增一个适配器。
- 负面：无同义词、拼写纠错与高级分词；ngram 索引体积较大；数据量达到百万级后需要重新评估。

## 被否决的替代方案
- Elasticsearch：能力最强但运维成本超出约束，留作演进路径（拆分 Discovery 时一并考虑）。
- `LIKE %keyword%`：无相关度、无法利用索引，仅作为教学对照保留。
